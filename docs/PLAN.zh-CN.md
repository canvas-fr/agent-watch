# Agent Watch 计划

> 更新：0.2.0 已实现持续采集、状态核心、菜单栏、提醒和事件桥。下文第0阶段描述是探测器的历史范围；当前监控器能力及未完成事项以 README.md 为准。

## 目标

Agent Watch 首发为 SwiftUI / AppKit 原生 macOS 应用，用于汇总多个原生 AI 应用的运行与任务状态。目标清单按产品和模式分别核对：

- 豆包
- Antigravity
- Gemini 桌面版
- ChatGPT、Codex
- Claude Chat、Claude Cowork、Claude Code
- DSH Desktop
- Devin
- WorkBuddy

应用进程存在只说明应用在运行，不能单独证明任务仍在执行、已经完成或已经失败。界面和记录必须保留状态来源与新鲜度；无法判断时标为“未知”。

## 当前实现边界：第 0 阶段

当前确认实现的范围仅为只读的安装与运行元数据、可选的 macOS 辅助功能（Accessibility，AX）角色统计，以及明确文件路径是否存在的元数据。路径检查只报告存在性，不读取文件内容。

第 0 阶段不读取聊天正文或截图，不修改应用配置，不激活或切换应用。AX 未授权或不可用时，相关统计应显示不可用或未知，不得推断为零。

本计划不把后续适配器、任务状态识别、后台完成判定或多窗口区分写成已交付能力。

## 界面和交互目标

菜单栏汇总运行中和需要处理的会话数量，展开后显示应用、可选任务名称、状态、持续时间及返回按钮。提供可固定在屏幕边缘的小面板，宠物是后续可选外观。默认仅在本轮结束、等待授权、等待用户回答或失败时提醒，同一事件只提醒一次。尽量返回具体会话，无法定位时标明只能打开应用。后台观察保持当前窗口焦点。

这些交互尚未在第 0 阶段实现。后续由统一事件驱动，避免界面自行读取各应用数据。

## 状态与证据原则

计划中的任务状态为：运行、等授权、等回答、本轮结束、失败、取消、未知。“本轮结束”只表示当前轮次结束，不等于父任务、会话或整个工作流结束。

每条状态都应保留来源和新鲜度。来源应标明是应用提供、AX 观察、进程/安装元数据，还是其他明确记录的来源；新鲜度应能区分新鲜、陈旧、未知。缺少可验证信号时使用“未知”，不得用推测补齐。

Parent 与 subagent 是不同实体，分别保留标识、父子关系和状态历史。只有明确关联的子代理事件才能挂到对应 parent；单个子代理终止不改变 parent 状态。

## 当前开发顺序

用户已明确功能优先，后续视觉参考 CC Switch。日常以 macOS 状态栏显示运行、待处理和未读结束数量，点击后展开详情。先完成逐来源接入与验收，再调整视觉；未知状态不表示待命。
